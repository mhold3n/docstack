# Maintain a docs verification skill

A docs verify map rots when the corpus moves. This skill is the upkeep loop for a skill generated by `/create-docs-verify-skill` (or any project-local docs verification skill with a surface map). The unit of rigor is the docs surface, not every sentence.

## Outcomes

Pick one, and say which:

- **clean** — every surface got source and live coverage; nothing worth shipping. No branch, no PR.
- **changed** — one PR ships proven skill, harness, or map corrections.
- **blocked** — coverage could not finish or a proven fix could not ship without risk. Name what blocked it.

## Edit scope

Edit the verification skill's own directory (its SKILL.md, features/ or surfaces/, and any harness scripts it owns). Never "fix" product docs during a maintain run by papering over a real corpus regression; report product drift separately.

## Pass

0. **Locate the target.** Find the docs verification skill (common path: `.cursor/skills/verify-docs-*/`). More than one candidate → ask which one; none → stop and point at `/create-docs-verify-skill`.

1. **Index hygiene.** Read the surface map README and glob its sibling files. Fix missing, extra, duplicate, or dead entries.

2. **Source wave.** One readonly subagent per surface file, launched concurrently. Each explains how that docs surface works from the corpus. Flag map drift with citations when evidence supports it. Return one concise live-verify recipe. Children never edit files.

3. **Reconcile.** Every surface file has a returned summary. Merge overlapping recipes. Spot-check cited drift.

4. **Live pass.** Required even when source looks clean. Run the verification skill's Launch commands. Exercise every surface at least once. Capture evidence at named locations. Mark a surface `verified-unreachable` when you cannot reach it, and record the concrete prerequisite plus the route attempted.

5. **Triage.** Wrong or missing surface description → map drift, fix it. Working corpus the harness cannot drive → harness gap, fix it. Real docs defects → report them; keep them out of this PR unless the user asked to fix product docs in the same run.

6. **Ship or stop.** For changed: one PR of proven corrections. For clean or blocked: no PR, report coverage without spin.
