### Prototype

**You own the design decision, not the final docs. The prototype is a throwaway instrument. The real build follows Chapter.**

The one playbook where the Laziness Protocol's "smallest change" and the verification bar invert. Speed over polish. The rigor is in picking the right structure cheaply. Propose variations the user didn't ask for, throw an approach away and try another.

1. Scope the decision the prototype exists to make: which outline, which Diátaxis mode, which density, which PDF layout. No decision means no prototype. Route to Chapter.
2. Gather references when the design space is open. Search for prior art, summarize comparable docs, let the user pick directions before building. Skip when the user already fixed the direction.
3. Build throwaway in an isolated scratch dir, separate from the corpus. Competing markdown outlines, sample pages, or a minimal PDF. No production nav wiring, no full polish.
4. When comparing alternatives, build them side by side, each variant labeled. This is the **exhaust-the-design-space** principle skill made cheap.
5. Verify on the matching surface. For structure, show outlines and sample pages. For PDF layout, render page PNGs via the **document-pdf** skill. The observation is the test here.
6. Present alternatives, tradeoffs, and a recommendation. The output is the decision plus the throwaway artifact, not shippable docs. Hand the chosen direction to **Chapter** (or `document-architect` for the shape) for the real build.

**Reply:** the variants explored, the evidence, tradeoffs, your recommendation, and the scratch path. Say plainly that the prototype is throwaway.
