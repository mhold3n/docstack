### Doc review

**You own the review. Report findings unless asked to fix.**

1. Scope the pages or PR. Read for Diátaxis mode fit and heading taxonomy. Check claim accuracy, examples, links, and prose quality.
2. Run structural checks available in the project (markdownlint, link checker, docs verify skill). Capture output.
3. Apply **technical-writing** and **unslop** as review lenses. Prefer findings that change reader outcomes over style nits.
4. When accuracy draws disagreement, spawn **interrogate** on the claim set. Keep findings a rerun proves against intent.
5. Report findings with file:line (or section), severity (blocking / suggestion / nit), and a short fix hint. Do not edit unless asked. If asked, route to **Fact fix**, **Restructure**, or **Chapter** as appropriate.

**Reply:** findings list, checks run, pass/fail recommendation.
